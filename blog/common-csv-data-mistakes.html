Common CSV Data Mistakes and How to Fix Them

April 2026 · 8 min read · By Stephen Bwami

A spreadsheet can look tidy and still contain errors that quietly change your totals, counts and conclusions. CSV files are especially easy to overlook because they are plain text: a value can be in the wrong format without looking obviously broken.

The safest approach is to inspect a dataset before analysing it, understand what each column is meant to represent, and make corrections you can explain and reproduce. Here are common problems to look for and practical ways to handle them.

1. Inconsistent date formats

A date such as 04/05/2026 can mean 4 May or April 5 depending on the convention. Mixing formats can lead to incorrect sorting, grouping and time-based calculations. Some spreadsheet applications may also interpret dates differently when a file is opened on another computer.

How to fix it: establish the date convention from the source or data owner, parse values using that known format, flag values that cannot be interpreted, and store dates consistently. ISO-style dates such as 2026-05-04 are useful for exchanging data because the year, month and day are unambiguous.

from datetime import datetime

raw_date = "04/05/2026"
parsed = datetime.strptime(raw_date, "%d/%m/%Y")
print(parsed.strftime("%Y-%m-%d"))

Do not guess the format from one row. Confirm it against the dataset documentation or a trusted sample.

2. Missing and blank values

A blank cell, NA, null, - and 0 are not necessarily the same thing. Zero may be a valid measurement, while a blank may mean the information was not collected. Treating all of them as zero can distort averages and totals.

How to fix it: measure how many values are missing in each important column, investigate why they are missing, then choose a rule that fits the field. You might leave a value missing, exclude a row from a particular calculation, or fill it using a documented method. Record the decision.

3. Duplicate records

Duplicates can inflate customer counts, sales totals or survey responses. But two rows with the same name are not automatically duplicates: two different people can share a name, and one customer can make multiple purchases.

How to fix it: identify the field or combination of fields that should uniquely identify a record, such as an order ID or a member ID plus transaction date. Check exact duplicates separately from possible duplicates that need review. Keep a copy of removed rows when the dataset is important.

4. Numbers stored as text

Values such as "1,250", "KES 800" or numbers with leading spaces may be imported as text. Sorting can then become alphabetical rather than numeric, and calculations may fail or silently omit values.

How to fix it: remove only known formatting characters, convert the column to a numeric type, and inspect values that fail conversion. Keep currency and unit information in a separate field where possible; do not remove symbols blindly if they carry meaning.

5. Inconsistent text and categories

Nairobi, nairobi and Nairobi may represent the same category. In other datasets, similar-looking labels may have different meanings. Inconsistent spelling and extra spaces can split one category into several groups in a chart.

How to fix it: trim unnecessary spaces, standardise letter case where appropriate, and create an explicit mapping for known variants. Review the unique values before merging categories so you do not combine genuinely different labels.

6. Header, delimiter and encoding problems

CSV does not always mean comma-separated in practice. Some exports use semicolons or tabs. A file can also contain duplicate column names, unnamed columns, unexpected line breaks or text encoded in a way that displays characters incorrectly.

How to fix it: inspect the first few lines of the raw file, confirm the delimiter and text encoding, check that every row has the expected number of fields, and rename unclear headers. When a field contains commas, it should be quoted correctly so the comma is not treated as a column separator.

A simple validation checklist

  • Do the column names describe the information clearly?
  • Does each column contain the expected type of value?
  • Are dates, units and category labels consistent?
  • Have missing values and duplicates been investigated?
  • Do row counts and key totals still make sense after cleaning?
  • Can another person understand the changes you made?

Final thought

Data cleaning is not about making a file look perfect. It is about making the meaning of the data dependable. The best correction is one supported by context, documented clearly and checked against the original. If you cannot explain why a value was changed, pause before changing it.
