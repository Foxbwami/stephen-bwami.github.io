How I Clean CSV Files for Data Analysis

March 2026 · 10 min read · By Stephen Bwami · Expanded November 2026

When I work with a CSV dataset, I avoid jumping straight into charts or calculations. My first priority is to understand what the file contains and whether its values can be trusted for the task at hand.

This article walks through a practical workflow using Python and pandas. The example is intentionally general: cleaning rules should always be adapted to the meaning and source of the actual dataset.

1. Preserve the original file

I keep the raw file unchanged and create a separate working copy. This protects the source data and makes it possible to compare the before and after versions. For important work, I also keep a note of the file name, source and date received.

2. Inspect the structure

Before changing values, I check the number of rows and columns, sample records, column names, data types and missing-value counts.

import pandas as pd

df = pd.read_csv("input.csv")

print("Rows and columns:", df.shape)
print(df.head())
print(df.info())
print(df.isna().sum())

At this stage I want to understand the dataset: what one row represents, which columns are identifiers, which fields are required and what units are being used.

3. Standardise column names

Column names with extra spaces or inconsistent capitalisation make code harder to maintain. I use a consistent naming convention, while preserving the original meaning of each heading.

df.columns = (
    df.columns
      .str.strip()
      .str.lower()
      .str.replace(" ", "_")
)

For complicated headers, review the result to make sure two different columns have not accidentally become identical.

4. Clean text carefully

Leading and trailing spaces are common in exported files. They can cause categories that look identical to be treated as different values. I trim whitespace in text columns, then inspect unique values in important categorical fields.

text_columns = df.select_dtypes(include="object").columns

for column in text_columns:
    df[column] = df[column].str.strip()

print(df["status"].value_counts(dropna=False))

Do not automatically change all text to uppercase or lowercase if letter case has meaning, such as product codes or passwords. Standardise only fields where the convention is clear.

5. Investigate missing values

I check which columns contain blanks and how many records are affected. Then I decide what to do based on the role of each field. A missing optional comment may be harmless; a missing transaction date may make a record unsuitable for a time-based analysis.

missing_summary = df.isna().sum().sort_values(ascending=False)
print(missing_summary[missing_summary > 0])

Possible treatments include retaining the missing value, filling it with a justified value, or excluding a record from a specific calculation. I avoid filling every blank with zero because zero may represent a real measurement.

6. Check duplicates using the right key

First I check exact duplicate rows. Then I consider whether the dataset has a unique identifier. Removing duplicates based only on a person's name or a date can delete legitimate records.

print("Exact duplicate rows:", df.duplicated().sum())

# Only use this if order_id should uniquely identify each row:
# df = df.drop_duplicates(subset=["order_id"])

The correct key depends on the data model. In a transaction file, one customer may correctly appear in many rows.

7. Convert data types and validate formats

Dates, numbers and categories should use appropriate types. Conversion errors should be reviewed rather than silently ignored. For a date column whose format is known:

df["order_date"] = pd.to_datetime(
    df["order_date"],
    format="%d/%m/%Y",
    errors="coerce"
)

df["amount"] = pd.to_numeric(
    df["amount"].str.replace(",", "", regex=False),
    errors="coerce"
)

errors="coerce" converts unparseable values to missing values. Check those new missing values and investigate the original entries before deciding how to handle them. The date format and amount-cleaning rule above are examples; they should match the actual source file.

8. Validate and save a separate output

After cleaning, I compare row counts, missing values, key totals and date ranges with the original. I check that identifiers remain unique where expected and that the cleaned values are plausible. Unexpected changes deserve investigation.

print("Final shape:", df.shape)
print(df.dtypes)
print(df.isna().sum())

df.to_csv("cleaned_output.csv", index=False)

I also keep a short cleaning log: the issue found, the rule applied, the number of affected records and any unresolved limitations.

9. Review failed conversions instead of hiding them

One risk with automated cleaning is turning invalid values into missing values and then forgetting that the conversion failed. After using errors="coerce", compare the newly missing values with the original strings. This makes it possible to distinguish genuinely blank cells from values that could not be parsed.

raw = pd.read_csv("input.csv", dtype={"amount": "string"})

amount_text = raw["amount"].str.replace(",", "", regex=False)
amount_numeric = pd.to_numeric(amount_text, errors="coerce")

failed = raw.loc[
    amount_text.notna() & amount_numeric.isna(),
    ["amount"]
]
print("Values needing review:")
print(failed.drop_duplicates())

This example assumes that commas are thousands separators. If the source uses commas as decimal separators, the rule must be different. Always confirm regional number conventions before converting currency or measurements.

10. Add validation rules that match the data

Validation checks can catch problems before a cleaned file is delivered. Examples include checking that required IDs are present, dates fall within the source period, quantities use an expected range, and a key field is unique in a table where uniqueness is required.

# Examples only: adapt these rules to the dataset
assert df["order_id"].notna().all()
assert df["amount"].dropna().ge(0).all()

duplicate_ids = df[df["order_id"].duplicated(keep=False)]
print("Order IDs to review:", len(duplicate_ids))

Do not apply a rule just because it is easy to write. Negative amounts, for example, may represent refunds. A failed check should trigger investigation, not automatic deletion.

11. Keep a simple cleaning log

A cleaning log makes the process understandable to another person. Record the issue, the rule applied, how many rows were affected, and the validation performed. Also note decisions that were not made because the available information was insufficient.

IssueActionEvidence / check
Spaces in branch namesTrimmed leading and trailing spacesReviewed distinct labels
Unparseable datesFlagged for reviewCompared with source export
Repeated order keyNot deleted automaticallyChecked order-level rules

12. Prepare the output for someone else

Use a clear output name, preserve identifiers and document the column meanings. If the file will be opened in spreadsheet software, check that dates, long numbers and leading-zero codes display correctly. Deliver the cleaned data with a short summary of what changed and any remaining issues, rather than sending a file with no explanation.

Conclusion

A reliable cleaning process is deliberate and repeatable. Inspect first, make changes that are supported by the data's meaning, validate the outcome and preserve the original. The goal is not simply a neat spreadsheet; it is a dataset whose limitations and structure you understand.
